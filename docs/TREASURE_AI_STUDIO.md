# Treasure AI Studio で使う

## 作業フォルダと MEMORY.md

- **生成物は「my」フォルダに置きません。** Treasure AI Studio では、本人しかアクセスできない `my` フォルダが自動で作られます。ここに置くと他のメンバーに共有できないため、Studio は `my` 以外のフォルダ（既定はワークスペース直下の `golden-path/`）を作成し、Workflow プロジェクト・データ確認の SQL・レポートとダッシュボード・運用 Skill・作業記録をすべてその中に置きます。CLI（`gp-cli.mjs`）も `my` の中への書き出しをエラーにします。
- **作業記録は `golden-path/MEMORY.md` に時系列で残ります。** 構築と運用は段階を追って、担当者をまたいで進むため、各段階（準備・ヒアリング・データ確認・Workflow 生成・push と初回実行・ダッシュボード作成、その後の最新化・追加分析・設定変更・調査）の実施内容、確定した設定と根拠、要確認事項と確認先、次にやることを、日時と担当者付きで古い順に追記します。次の担当者は最後のエントリから再開できます。

```text
<共有フォルダ>/golden-path/                       ← my 以外
├─ MEMORY.md                                     ← 作業記録（時系列）
├─ golden_path/                                  ← Workflow プロジェクト
├─ _discovery/                                   ← データ確認用 SQL
├─ golden_path_reports/<YYYYMMDD>/               ← bundle.json・ダッシュボード HTML
└─ .claude/skills/td-ec-golden-path-analytics/   ← 運用 Skill（config/install.yml）
```

以前のバージョンで `my` の中に構築していた場合は、次に Skill を使ったときに `my` 以外のフォルダへのコピーを提案します（`my` 側は消しません。TD 上の Workflow とテーブルはそのまま使えます）。

## 1. 初期構築

次の文をそのまま貼り付けます（ビューアーのトップページからもコピーできます）。

```text
https://github.com/tsukaharakazuki/td-ec-golden-path-analytics
このURLを読み込んで、ECゴールデンパス分析（td-ec-golden-path-analytics）の初期構築をしたいです。
```

条件を足したい場合の例:

```text
https://github.com/tsukaharakazuki/td-ec-golden-path-analytics
このURLを読み込んで、ECゴールデンパス分析の初期構築をしたいです。
- 対象ブランドは mix.tokyo、Webログは web_log.pageviews です
- 店舗の購買（POS）まで含めてください
- tdx は読み取り専用で確認してから、push と実行の前に必ず確認してください
- 自分しかアクセスできない「my」フォルダには何も置かず、my 以外のフォルダ（例: golden-path）を作成して、生成物はすべてその中に置いてください
- 作業は段階を追って・担当者をまたいで行うので、作業フォルダの MEMORY.md を最初に読み、各段階の内容・確定事項・要確認事項・次にやることを日時と担当者付きで時系列に追記してください
```

用意しておくとスムーズなもの:

- Webログ・会員・POS・商品マスタの DB 名とテーブル名
- 購入完了ページ（Thanks ページ）の URL と、注文ID の入っている場所
- utm の付け方のルール（メール・LINE・広告）
- 購入直前に経由する外部サービス（決済・会員アプリなど）が分かれば

## 2. 日々の更新

```text
ゴールデンパス分析を最新にしてください。
Workflow を実行して、終わったらダッシュボードを更新してください。
```

別の担当者が続きを引き継ぐとき:

```text
golden-path フォルダの MEMORY.md を読んで、前回の続きからゴールデンパス分析の作業を進めてください。
```

Workflow の実行には、Webログの件数と期間に応じて数分〜数十分かかります。

## 3. 追加分析

```text
PMax は実際の購買にどう貢献している？ ラストクリックと線形で比べて
メール「season_sale」で見られた商品と、同じ商品の購入（店舗含む）を教えて
ロイヤル顧客はアウターをどんな経路・サイト内行動で買っている？
いちばんスコアが高いゴールデンパスは、なぜ高い？
```

## 4. 設定の変更

```text
ゴールデンパスの設定を変更したいです。除外するリファラに〇〇を追加してください。
```

設定（`params.yml`）を直し、静的検査 → `tdx wf push --dry-run` で差分確認 → 承認後に push します。

## 安全のための約束

- tdx の実行は事前に内容を示して承認を取る。初期構築のデータ確認は読み取り専用
- `tdx wf push` / `tdx wf run` は、それぞれ明示的な了承を得てから
- 会員ID・メールアドレスなどの生値をチャットやファイルに出さない
- API キーなどの秘密情報を設定ファイルや Skill に書かない
- ダッシュボードの HTML / JSON はブラウザ内だけで動き、外部へ送信しない
- 生成物は `my` 以外の共有フォルダに置き、作業の経緯を MEMORY.md に残す（API キーや個人情報の生値は書かない）

## 確認ポイント

- 作業フォルダ・Workflow プロジェクト・ダッシュボード・`.claude/skills/` が `my` 以外の共有フォルダにあり、他のメンバーが開けること
- MEMORY.md の最後のエントリに、要確認事項と次にやることが書かれていること
