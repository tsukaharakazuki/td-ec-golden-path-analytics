## I. フリークエンシー・サンキー（購入回数の推移）→ `frequency_sankey`

初回購入（F1）から N 回目までに「何を買ったか」がどう移り変わり、最後にどのランクに育ったかを見る図。POS の購買明細（G）が必要。

| # | 質問 | 既定 / 例 |
|---|---|---|
| I1 | 何回目まで並べるか | 5 回（F1〜F5）。購入頻度の低い商材は 3〜4 回 |
| I2 | 移り変わりを見る軸（複数可） | 商品カテゴリ `category`・ブランド `brand`・1注文の合計金額 `amount_band`・購入チャネル `channel`（EC/店舗）・独自の商品系統 `custom` |
| I3 | 独自の商品系統（定番シリーズ・お試しセットなど）でまとめたいか | まとめたい場合は、明細から系統を決めるルールを聞いて `custom_expr` に式で書く（例: 商品名に「コラーゲン」→ ACG）。呼び名は `custom_label` |
| I4 | 1注文の金額帯の区切り | `3000,5000,10000,20000,30000`（円）。客単価の分布を見て提案してよい |
| I5 | 最終列に何を置くか | 累計購買金額ランク（`amount_rank`）／RFM セグメント（`rfm_segment`）／置かない。会員ランク制度があれば、その区切りと名前を `rank_thresholds` / `rank_labels` に（例: `30000,60000,100000` / `SEED,SPROUT,BLOSSOM,FRUIT`） |
| I6 | 新規顧客の定義 | POS 期間の最初の 365 日に購入が無く、その後に初めて購入した会員（`new_customer_gap_days`）。POS の保持期間が短い場合は小さくする |
| I7 | 1注文で複数カテゴリ（複数ブランド）を買った人の既定の見せ方 | 下の説明を見せて選んでもらう。3 通りとも集計され、ダッシュボードで切り替えられる |
| I8 | 対象の購買と、表示する値の数 | 店舗＋EC（`all`）／EC のみ（`ec`）。各軸の上位 6 件（残りは「その他」） |

I7 の説明（そのまま見せてよい）:

- **金額最大の値（primary・既定）** — その注文で金額が一番大きいカテゴリを、その回のカテゴリとする。人数がそのまま保たれ、「主に何を買ったか」の流れが読みやすい。併買の情報は図から消えるが、各ノードの「複数購入の比率」と組み合わせの表で補う
- **「複数」にまとめる（mixed）** — 2 カテゴリ以上の注文は「複数カテゴリ」という 1 つの箱にする。まとめ買いがどの回で増えるか、まとめ買いした人がその後どこへ流れるかが見える。箱の中身は組み合わせの表で見る
- **金額比で按分（split）** — 1 人を金額の比率で分けて流す（例: アウター 2 万円 + トップス 5 千円 → 0.8 人 + 0.2 人）。すべてのカテゴリが図に出るが、人数は「人相当」になる

1 人を各カテゴリで 1 人ずつ数える（重複して数える）方法は、列の合計が実際の人数より大きくなり、サンキー図の「帯の太さ＝人数」が成り立たないため採らない。
